# ჩემი უბანი — პროექტის გადაცემა და GitHub-ზე ატვირთვა

ეს პაკეტი მომზადებულია შენ მიერ გამოგზავნილი არქივიდან. არქივში აღმოჩნდა **4.55.0 ვერსია, Android კოდი 39**. ის არ არის უფრო ახალი 4.56.0 ან Play Console-ში ბოლო ატვირთული ვერსიის დადასტურებული ასლი.

## რა არის გაკეთებული

- აპის კოდი, Android პროექტი, რესურსები, სერვერული SQL და Edge Functions შენარჩუნებულია.
- პირადი PDF-ები, სასწავლო გეგმები, CV, `node_modules`, ძველი არქივები და ადგილობრივი ხელმოწერის ფაილები გასაზიარებელი პაკეტიდან გამოტოვებულია.
- რეალური Supabase/Expo კონფიგურაცია ჩანაცვლებულია მაგალითებით; ადმინისტრატორის პირადი ნომრის ადგილას არის `500000000`. ეს ნომერი მხოლოდ მაგალითია და უფლებები მას რეალურ ბაზაში არ უნდა მიენიჭოს.
- დამატებულია README, სტრუქტურის აღწერა, დაყენება/აწყობა, ტექნიკური მიმოხილვა, ავტომატური შემოწმებები და `.gitignore`.
- ავტომატური გამოქვეყნება გამორთულია; GitHub Actions მხოლოდ კოდსა და ტესტებს ამოწმებს.

## როგორ წარადგინო

შეგიძლია ასე აღწერო: „ჩემი უბანი არის ქართულენოვანი სამეზობლო აპლიკაციის პროექტი. აქვს პოსტები, პირადი და ჯგუფური ჩათი, დღის ფოტო, მარკეტი, სპეციალისტები და ახლომდებარე ობიექტები. მობილური ნაწილი Expo/React Native-ზეა, ეკრანების ძირითადი ნაწილი WebView-ში მუშაობს; backend არის Supabase. პროექტს თან ახლავს აწყობის სკრიპტები და ავტომატური რეგრესიული შემოწმებები.“

ეს აღწერა ტექნიკურად ზუსტია. ნუ წარადგენ როგორც მთლიანად native ეკრანებით აშენებულ აპს, სრულად აუდიტირებულ სისტემას ან 30 000 ერთდროულ მომხმარებელზე შემოწმებულ პროდუქტს. შენს პირად წვლილსა და გამოყენებულ დახმარებასაც ზუსტად აღწერდე.

## პირველადი შემოწმება

Node.js 24-ის დაყენების შემდეგ PowerShell გახსენი **ამ ახალ საქაღალდეში**:

```powershell
npm ci --ignore-scripts
npm ci --prefix tooling --ignore-scripts
npm run check
```

ეს ამოწმებს წყაროს და შერჩეულ ოფლაინ ტესტებს. რეალურ მომხმარებლებს არაფერი ეგზავნება. აპის სრული მუშაობისთვის შენი სერვერის კონფიგურაცია და Firebase ფაილები ცალკე უნდა აღადგინო — იხილე `SETUP.md`.

## GitHub-ზე ატვირთვა

1. GitHub-ზე შექმენი ახალი **Private** რეპოზიტორია, მაგალითად `chemi-ubani`. თავიდან ნუ დაამატებ ავტომატურად README-ს ან ლიცენზიას — README უკვე გვაქვს.
2. ZIP გაშალე ცალკე საქაღალდეში. შენს სამუშაო Project საქაღალდეს არ გადააწერო.
3. ახალი პროექტის საქაღალდეში გაუშვი:

```powershell
git init -b main
git add .
git status --short
```

4. სიაში არ უნდა იყოს `.jks`, `.keystore`, `config.public.local.json`, `google-services.json`, `node_modules`, APK/AAB ან პირადი დოკუმენტები. შემდეგ:

```powershell
git commit -m "Prepare Chemi Ubani source and engineering documentation"
git remote add origin https://github.com/YOUR-USERNAME/chemi-ubani.git
git push -u origin main
```

`YOUR-USERNAME` შეცვალე შენი ანგარიშის სახელით. ეს ნაბიჯები ახალი, ცარიელი რეპოზიტორიისთვისაა. უკვე არსებულ რეპოზიტორიას არ გამოიყენო ისტორიის/შიგთავსის გადამოწმების გარეშე და `--force` არ დაამატო.

5. GitHub-ის Actions ჩანართში ნახე შემოწმების შედეგი. ამ გარემოში ჩატარებული ტესტები აღწერილია `VALIDATION.md`-ში; GitHub-ზე გაშვებული CI ჯერ ცალკე უნდა დასრულდეს.
6. თუ ვინმეს განხილვისთვის აძლევ, Private რეპოზიტორიაზე კონკრეტული თანამშრომელი დაამატე. გასაღებები და სერვერის პაროლები კოდის რეპოზიტორიით არ გააზიარო.

## როგორ არის აწყობილი

- `App.js` — ტელეფონის ფუნქციები: კამერა, Push, უკან დაბრუნება და WebView-სთან კავშირი.
- `prototype-v4.55.0.html` — ძირითადი ეკრანები და სტილები.
- `src/` — ჩათის, ავტორიზაციის, დღის ფოტოს, მარკეტის, რუკებისა და სხვა ფუნქციების JavaScript მოდულები.
- `scripts/embed-html.mjs` — ფუნქციებს აერთიანებს და ქმნის `src/appHtml.js`-ს.
- `supabase/` — მონაცემთა ბაზის ცვლილებები და სერვერული ფუნქციები. **ცარიელი ბაზის სრულად ასაწყობი საწყისი სქემა არქივში არ არის.**
- `tests/` და `tooling/` — ავტომატური შემოწმებები და მათი დამოკიდებულებები.
- `android/` — Android-ის ასაწყობი პროექტი.

დეტალური დიაგრამა და მოდულების ცხრილი არის `ARCHITECTURE.md`-ში. დარჩენილი საინჟინრო საკითხები — `TECHNICAL-REVIEW.md`-ში. მათი არსებობა არ ნიშნავს, რომ პროექტი არაფრად ვარგა; მნიშვნელოვანია, რომ მას რეალისტური აღწერა და შემდგომი სამუშაოს გეგმა აქვს.
